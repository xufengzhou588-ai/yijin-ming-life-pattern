# BaziCoreOutput v1 Product Discussion

## 已完成，建议保留

- 确定性核心层：输入生日、性别、出生地后生成四柱、藏干、五行、十神、大运、流年和证据链。
- Schema 校验：每次生成后校验 `BaziCoreOutput v1`，避免前端展示层绕开核心合同。
- 简化用户层：默认展示总览、事业、财富、关系、决策风格，不直接暴露 Canonical JSON。
- 质检条：显示输入完整度、Schema 状态、证据链数量。
- 中国地区三级选择：国家固定中国，省市选择后自动填时区和经纬度。
- 双语切换：首页支持中文和英文，面向后续美服 App Store。
- 样例命盘：提供上海、广州、乌鲁木齐样例，便于快速测试不同时间和地区。
- 经典参照：以《易经》象义作为解释层，不参与四柱排盘计算。
- 时间节奏：把大运和近年流年从表格转成可读时间线。

## 值得继续做，但要谨慎

- 真太阳时：专业上重要，普通用户不应手填。建议后端根据城市经度自动计算，并在高级设置中说明。
- 城市库扩展：当前只覆盖主要城市。上线前应补全中国地级市，海外版再补海外城市。
- AI 咨询师：应只读取结构化中间层和证据链，不直接根据生日自由发挥。
- 冲突裁决：需要独立 Rule Engine，把五行、十神、大运、流年之间的冲突显式评分。
- 校盘系统：可做成高级功能，通过用户反馈事件校正时辰可信度。
- App Store 合规：避免承诺命运、财富、婚姻结果，文案定位为文化、反思和决策辅助。

## 需要讨论是否实用

- 姓名分析：八字核心不需要姓名。姓名学可作为独立模块，但不要混入 BaziCoreOutput v1。
- 用神 / 格局裁决：用户会期待，但第一阶段不建议上线为强结论，容易造成系统耦合和争议。
- 每日运势推送：商业上有价值，但容易变成低质量内容，需要等规则层稳定后再做。
- 付费报告：现在可以做报告雏形，但不建议过早商业化，先验证用户是否理解和信任结果。
- 社交分享：传播有价值，但涉及隐私和敏感出生信息，先不做。

## 暂不建议做

- 让用户手填经纬度。
- 默认展示完整 JSON。
- 直接给“发财、结婚、灾祸”等绝对判断。
- 把《易经》原文当作排盘计算依据。
- 在核心层加入 LLM 文案。
