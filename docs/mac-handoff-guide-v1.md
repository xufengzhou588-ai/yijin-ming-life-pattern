# Mac Handoff Guide v1

## What This Package Contains

This Windows handoff package contains:

- deterministic Python backend and tests;
- web prototype at `web/index.html`;
- legal draft pages under `web/legal/`;
- SwiftUI iOS shell source under `ios/MINGLifePattern/`;
- StoreKit product definitions and review notes under `ios/`;
- App Store submission, privacy, and validation docs under `docs/`.

## Mac Goal

Turn the source skeleton into a buildable Xcode project, run StoreKit sandbox
purchase/restore, then prepare TestFlight.

## Step 1 - Unzip

Unzip the handoff archive anywhere on the Mac, for example:

```bash
~/Projects/Yijin
```

## Step 2 - Create Xcode Project

1. Open Xcode.
2. Choose `File > New > Project`.
3. Select `iOS > App`.
4. Product Name: `MINGLifePattern`.
5. Team: choose the Apple Developer account.
6. Organization Identifier: `app.mingpattern`.
7. Bundle Identifier: `app.mingpattern.life`.
8. Interface: SwiftUI.
9. Language: Swift.
10. Minimum iOS target: iOS 17.0 for the sprint build.

## Step 3 - Import iOS Source

Copy these folders into the Xcode project and add them to the app target:

```text
ios/MINGLifePattern/App
ios/MINGLifePattern/Models
ios/MINGLifePattern/Services
ios/MINGLifePattern/Stores
ios/MINGLifePattern/Support
ios/MINGLifePattern/Views
ios/MINGLifePattern/Resources
```

Important:

- Remove the default `ContentView.swift` generated by Xcode.
- Keep `MINGLifePatternApp.swift` as the app entry point.
- Add the Info.plist values from `ios/MINGLifePattern/Resources/Info.plist`
  to the target build settings or target Info tab.

## Step 4 - Configure URLs

For simulator testing you can point the app at a locally running server:

```text
MING_WEB_APP_URL=http://127.0.0.1:8787/app
MING_API_BASE_URL=http://127.0.0.1:8787
MING_PRIVACY_URL=http://127.0.0.1:8787/legal/privacy
MING_TERMS_URL=http://127.0.0.1:8787/legal/terms
MING_SUPPORT_URL=http://127.0.0.1:8787/support
```

For TestFlight/App Review these must become public HTTPS URLs.

## Step 5 - Run Backend Locally

On the Mac:

```bash
cd ~/Projects/Yijin
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python server.py
```

Then test:

```bash
curl http://127.0.0.1:8787/api/entitlement
```

## Step 6 - StoreKit Local Testing

Create a StoreKit Configuration file in Xcode using:

```text
ios/StoreKit/storekit-products-local.md
```

Products:

- `ming.pro.monthly`
- `ming.pro.yearly`

Attach the `.storekit` file to the Xcode scheme:

```text
Product > Scheme > Edit Scheme > Run > Options > StoreKit Configuration
```

## Step 7 - Backend StoreKit Stub for UI Testing

For local UI flow only:

```bash
BAZI_STOREKIT_STUB=1 python server.py
```

This lets the backend return a sandbox-like Pro entitlement from
`POST /api/app-store/transactions`.

Do not use this for TestFlight or production.

## Step 8 - Required Before TestFlight

1. Create App Store Connect app record.
2. Create subscription group `MING Pro`.
3. Create products:
   - `ming.pro.monthly`
   - `ming.pro.yearly`
4. Host legal/support pages on public HTTPS URLs.
5. Host backend on public HTTPS API URL.
6. Implement real App Store Server API validation.
7. Replace placeholder Info.plist URLs.
8. Build Archive and upload to TestFlight.

## Step 9 - App Review Packet

Use:

```text
docs/app-store-submission-packet-v1.md
ios/AppStoreConnect/review-notes.md
```

## Known Non-Negotiable Gap

The iOS StoreKit2 client skeleton exists, but real server-side Apple validation
is not implemented yet. App Review should not be submitted until
`POST /api/app-store/transactions` validates Apple signed transactions or App
Store Server API responses.
